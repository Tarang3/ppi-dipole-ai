# PPI + Dipole AI

**Live demo: https://ppi-dipole-ai.streamlit.app/**

A small, working web app that

1. **Predicts protein-protein interactions (PPI)** with a machine-learning model trained on human physical interactions from [STRING v12](https://string-db.org/).
2. **Computes protein dipole moments** from 3D structures (AlphaFold, RCSB PDB, or your own PDB file).

Enter two proteins as a **UniProt ID** (`P69905`), a **PDB ID with optional chain** (`1BRS:A`), a **raw sequence**, or **upload a PDB/mmCIF file**.

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

A trained model is included in `models/`, so the app works right away. To retrain from scratch (downloads ~16 MB from STRING, takes ~2 min):

```bash
python -m ppi_ai.train
```

Run the tests:

```bash
pip install pytest
pytest
```

## How it works

### Interaction prediction (`ppi_ai/features.py`, `ppi_ai/dataset.py`, `ppi_ai/train.py`)

- **Data**: STRING v12 human *physical* interactions with confidence score >= 900 are positives (20,000 sampled pairs).
- **Negatives**: degree-preserving shuffles. The proteins in the positive pairs are shuffled and re-paired, and any pair known to STRING is thrown out. Every protein shows up equally often in positives and negatives, so the model can't cheat by learning "hub proteins interact with everything". Plain random negatives make PPI models look much better than they really are.
- **Features** (369 per protein): amino-acid composition (20), conjoint triad (343; Shen et al., *PNAS* 2007), plus length, hydrophobicity (GRAVY), isoelectric point, net charge, aromaticity, and instability index.
- **Pair encoding**: `[a + b, |a - b|, a * b]`, which doesn't depend on order, so `f(A, B) == f(B, A)`.
- **Model**: scikit-learn `HistGradientBoostingClassifier`.

| Test set | Accuracy | Precision | Recall | ROC-AUC |
|---|---|---|---|---|
| Random 20% of pairs | 0.689 | 0.699 | 0.664 | 0.769 |
| Pairs where both proteins were never seen in training | 0.649 | 0.677 | 0.572 | 0.707 |

(Generated by `python -m ppi_ai.train`; full numbers in `models/metrics.json`.)

### Dipole moment (`ppi_ai/dipole.py`)

Each ionizable group (Asp, Glu, His, Lys, Arg, Cys, Tyr, N- and C-termini) gets a fractional charge at the chosen pH from the Henderson-Hasselbalch equation, using standard pKa values. The charge sits at the side-chain's charged atom(s). The dipole is taken about the center of mass:

$$\vec{\mu} = \sum_i q_i\,(\vec{r}_i - \vec{r}_{\text{cm}}), \qquad 1\ e\cdot\text{Å} = 4.803\ \text{D}$$

The app shows |mu| in Debye, |mu| per residue, net charge, the vector, and a 3D plot of the backbone, charged residues, and dipole direction.

Sanity check: barnase (1BRS:A) gets +2.1 e and barstar (1BRS:D) gets -6.0 e at pH 7, which matches their known charges (+2 / -6).

## Project layout

```
app.py               Streamlit UI
ppi_ai/features.py   sequence -> feature vectors
ppi_ai/dataset.py    STRING download + positive/negative pair construction
ppi_ai/train.py      training + evaluation (random split and unseen-protein split)
ppi_ai/predict.py    load model, predict probability
ppi_ai/dipole.py     charge assignment + dipole computation
ppi_ai/fetch.py      UniProt / AlphaFold / RCSB downloads
ppi_ai/resolve.py    user input -> protein (sequence + optional structure)
tests/               unit tests
```

## Limitations and next steps

- The model only sees sequences, not structures or protein language-model embeddings. Swapping in ESM-2 embeddings is the obvious next step for accuracy.
- The dipole model uses fixed pKa values and point charges, not per-residue pKa prediction (e.g. PROPKA) or partial atomic charges.
- Predictions are a screening score, not experimental evidence.
